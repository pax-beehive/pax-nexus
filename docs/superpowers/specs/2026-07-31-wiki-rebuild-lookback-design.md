# Wiki Rebuild Lookback Design

Date: 2026-07-31
Status: approved

## Problem

`POST /v1/wiki/rebuild` always clears all PageWiki-derived state and replays
every Session Lake stream from sequence 0. On corpora with long histories
(e.g. imported datasets), a full replay is slow and expensive: every session
costs LLM plan + edit calls. The operator has no way to say "rebuild the wiki
from only recent sessions."

## Decision

Extend the existing Reset & rebuild confirmation dialog on the wiki status
page with an optional **"Replay sessions since" calendar date input**. The
chosen date flows through `POST /v1/wiki/rebuild` into the rebuild
transaction, which pre-seeds ingestion cursors so that stale streams are
skipped.

### Semantics (user-confirmed)

- **Session-level granularity.** A stream whose latest event
  (`session_events.occurred_at`) is on or after the cutoff replays **in
  full from sequence 0** — no mid-session truncation. A stream with no
  event at or after the cutoff is skipped entirely.
- **Empty date = full rebuild** — exactly today's behavior.
- **Skipping is durable.** Skipped streams get their cursor set to
  `last_sequence`, so subsequent automatic scans do not pick them up. They
  return only via a later rebuild with an earlier date or no date.
- **Cutoff timestamp.** The browser converts the picked calendar date to
  local midnight and sends RFC3339. The backend treats it as an opaque
  instant; comparison is `occurred_at >= since`.
- `occurred_at` is the connector-supplied event time, so imported
  historical corpora (whose ingest `updated_at` is the import moment) cut
  correctly by their original activity dates.

## Backend

No new tables, no migration.

- **API model**: the hertz models are generated from
  `idl/team_memory.thrift` (`// Code generated by hertz generator. DO NOT
  EDIT.`). `struct RebuildWikiRequest {}` (team_memory.thrift:347) gains
  `1: optional string since`, then `make generate` refreshes
  `internal/teamnote/transport/httpapi/router/pagewiki/api`. Absent/empty
  means full rebuild. Malformed value → HTTP 400.
- **Handler** (`wiki_ingestion_endpoints.go` `RebuildWiki`): parse `since`
  with `time.Parse(time.RFC3339, …)`; pass the parsed time (zero value when
  absent) to the controller.
- **Controller** (`sessionconsumer.Controller.Rebuild`): signature becomes
  `Rebuild(ctx, scopeID string, since time.Time)`. The `Rebuilder`
  interface becomes
  `RebuildPageWiki(ctx, scopeID, processorName, processorVersion string, since time.Time)`.
  Zero `since` = full rebuild. Behavior otherwise unchanged (failure map
  reset, trigger nudge, auto-inject re-enabled).
- **Repository** (`internal/pagewiki/postgres/repository.go`
  `RebuildPageWiki`): inside the existing transaction, after deleting the
  processor cursors and before enabling ingestion, when `since` is non-zero
  run one statement:

  ```sql
  INSERT INTO session_processor_cursors
      (processor_name, processor_version, scope_id, agent_id, session_id, committed_sequence)
  SELECT $1, $2, stream.scope_id, stream.agent_id, stream.session_id, stream.last_sequence
  FROM session_streams AS stream
  WHERE stream.scope_id = $3
    AND stream.agent_id <> ''
    AND NOT EXISTS (
      SELECT 1 FROM session_events AS event
      WHERE event.scope_id = stream.scope_id
        AND event.agent_id = stream.agent_id
        AND event.session_id = stream.session_id
        AND event.occurred_at >= $4
    )
  ```

  Streams with recent activity get no cursor row, so `PendingStreams`
  (`last_sequence > COALESCE(cursor, 0)`) replays them from 0.
- The in-memory pagewiki repository used by tests mirrors the new
  `RebuildPageWiki` signature.

## Frontend

- **`ConfirmDialog`** gains an optional `children` slot rendered between
  the consequences list and the action row. No other behavior change.
- **`WikiStatusPage`**: new `rebuildSince` state (string, `YYYY-MM-DD` or
  empty). The rebuild dialog body holds a labeled native
  `<input type="date">` (calendar picker, no new dependency) plus helper
  text; when a date is chosen, the consequences list swaps the "every
  stream will be processed again" line for one that names the cutoff:
  "Sessions with no activity since <date> will be skipped." Confirm sends
  `new Date(rebuildSince + "T00:00:00")` serialized as RFC3339 (local
  midnight); empty input sends no `since` field. State resets when the
  dialog closes.
- **`api/wiki.ts`**: `rebuildWiki(signal, since?: string)` posts `{since}`
  only when provided.

## Testing

- **Repository integration test**: three streams — all events before the
  cutoff, straddling it, all after — assert the first gets
  `committed_sequence = last_sequence` and the other two get no cursor row;
  assert zero `since` seeds nothing (current behavior).
- **Handler test**: valid `since` reaches the controller parsed; malformed
  `since` → 400 and the controller is never called; absent `since` passes
  zero time.
- **Consumer unit test**: `Rebuild` forwards `since` to the `Rebuilder`
  fake verbatim and still clears the failure map.
- **Frontend DOM test**: picking a date puts RFC3339 `since` in the request
  body and the skip line in the dialog; leaving it empty omits `since`.

## Out of scope

- Filtering by anything other than time (agent, project, topic).
- Datetime-level precision in the picker (date-only is enough).
- Un-skipping streams without another rebuild.
