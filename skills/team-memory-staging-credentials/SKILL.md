# Staging credentials

Every credential the staging environment needs lives in Google Secret Manager
in project `paxtech-stg`. There is no credential file to find and no value to
paste: read what you need at the moment you need it.

## Rules

- **Read on demand, never persist.** Do not copy a secret into a file, an
  environment file, a commit, or chat. Pipe it straight into whatever consumes
  it.
- **Never print a secret.** To confirm you have the right value, compare a
  short hash instead:
  `gcloud secrets versions access latest --secret=NAME --project=paxtech-stg | shasum -a 256 | cut -c1-12`
- **`latest` is what runs.** Cloud Run resolves `latest` at instance start, so
  adding a new version rotates a key without a redeploy — but existing
  instances keep the old value until they restart.
- Prerequisite: `gcloud auth login` and `gcloud auth application-default login`
  as a principal with `roles/secretmanager.secretAccessor` on `paxtech-stg`.

## What is stored

| Secret | What it is |
|---|---|
| `oidc-client-secret` | WorkOS API key. Doubles as the OIDC client secret — WorkOS uses one value for both, so **it is stored once**; a second copy under another name would rot on rotation. |
| `workos-client-id` | WorkOS client ID. Not secret, but kept here so an apply needs nothing local. |
| `cloudflare-api-token` | Cloudflare DNS-edit token, scoped to the `paxtech.net` zone. Terraform uses it for the host record and the certificate authorization. |
| `extractor-api-key` | DeepSeek key. Serves both Team Note extraction and the Page Wiki maintainers. |
| `embedding-api-key` | OpenAI key, for semantic-recall embeddings. |
| `bootstrap-secret` | One-time claim for the first workspace owner. |
| `secret-pepper` | HMAC pepper for credential digests. Rotating it invalidates every issued agent credential. |
| `oidc-flow-secret` | Seals the short-lived OIDC flow cookie. Every instance must share it. |
| `database-url` | Cloud SQL DSN, including the password. |

The last four are generated by Terraform and therefore exist in its state
(`gs://paxtech-stg-tfstate`, private and versioned). The first five are added
out of band and never enter state.

## Reading one

```sh
gcloud secrets versions access latest --secret=<name> --project=paxtech-stg
```

Claiming the first workspace owner, for example, needs a successful OIDC login
first and then:

```sh
curl -X POST https://nexus-stg.paxtech.net/v1/bootstrap/claim \
  -H "X-PAX-Bootstrap-Secret: $(gcloud secrets versions access latest \
      --secret=bootstrap-secret --project=paxtech-stg)" \
  -H "Cookie: tm_human_session=<session cookie from the browser>"
```

## Running terraform apply

`deploy/terraform/staging` reads the Cloudflare token from the environment and
takes the WorkOS values as variables, so source them from Secret Manager:

```sh
cd deploy/terraform/staging
export CLOUDFLARE_API_TOKEN=$(gcloud secrets versions access latest \
  --secret=cloudflare-api-token --project=paxtech-stg)
CLIENT_ID=$(gcloud secrets versions access latest \
  --secret=workos-client-id --project=paxtech-stg)

TAG=$(git rev-parse --short HEAD)
REPO=asia-northeast1-docker.pkg.dev/paxtech-stg/team-memory
terraform apply \
  -var="oidc_issuer=https://api.workos.com/user_management/${CLIENT_ID}" \
  -var="oidc_client_id=${CLIENT_ID}" \
  -var="image=${REPO}/app:${TAG}" \
  -var="web_image=${REPO}/web:${TAG}"
```

## Rotating

```sh
printf '%s' '<new value>' | gcloud secrets versions add <name> \
  --project=paxtech-stg --data-file=-
```

Then restart the service so instances pick it up:

```sh
gcloud run services update team-memory --region=asia-northeast1 \
  --project=paxtech-stg --update-env-vars=ROTATED_AT=$(date +%s)
```

Two rotations are not just a new version:

- **`secret-pepper`** invalidates every agent credential ever issued. Every
  agent must re-enroll. Treat it as an incident response step, not maintenance.
- **`database-url`** must change the Cloud SQL password in the same breath, and
  Terraform owns that password. Rotate it through `terraform apply`, not by
  hand.
