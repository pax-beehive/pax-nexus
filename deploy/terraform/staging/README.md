# Staging environment

GCP project `paxtech-stg`, region `asia-northeast1`, reachable at
<https://nexus-stg.paxtech.net>.

## Shape

```
Cloudflare (proxied: TLS, WAF, DDoS)
  │  Full (strict) to origin
  ▼
Global external ALB  ── /v1/*, /healthz, /readyz ──►  Cloud Run  team-memory
  │                                                     │ unix socket
  │  everything else                                     ▼
  └──────────────────────────────────►  Cloud Run  team-memory-web
                                        (Caddy + built SPA)
                                                    Cloud SQL Postgres 17
```

One hostname serves both, so the browser sees a single origin: no CORS, and
the `SameSite=Lax` session cookies work unchanged. The split reproduces
`deploy/workstation/Caddyfile`, which is the tested specification of the same
routing for the workstation profile.

Cloud Armor admits only Cloudflare's published ranges, so nobody reaches the
origin directly and skips the WAF.

## Two decisions worth knowing

**The portal is a Cloud Run service, not a storage bucket.** A backend bucket
needs its objects readable by `allUsers`, which this organization's
domain-restricted-sharing policy forbids. Serving the files from a small
Caddy image avoids weakening an org-wide control, and gets the SPA fallback
(`/join` is a client-side route, not a file) from `try_files` rather than a
load-balancer 404 rewrite.

**The API runs as a single instance** (`min = max = 1`). `app.Run` starts
every background loop unconditionally, and the Page Wiki consumer, audit
consumer, maintenance loops, and operations maintenance hold no database
lease, so a second instance would double-process and pay twice for the same
LLM calls. Splitting into a scalable `api` plus a pinned `worker` needs a
mode switch and the rebuild state machine moved out of process memory.

## Applying

State lives in `gs://paxtech-stg-tfstate`. Credentials come from the
environment so nothing sensitive is committed or written into state:

```sh
set -a; . ~/.workos/staging.env; . ~/.cf/api.env; set +a
export CLOUDFLARE_API_TOKEN="$API_TOKEN"

TAG=$(git rev-parse --short HEAD)
REPO=asia-northeast1-docker.pkg.dev/paxtech-stg/team-memory

terraform apply \
  -var="oidc_issuer=https://api.workos.com/user_management/${WORKOS_CLIENT_ID}" \
  -var="oidc_client_id=${WORKOS_CLIENT_ID}" \
  -var="image=${REPO}/app:${TAG}" \
  -var="web_image=${REPO}/web:${TAG}"
```

## Building and pushing

```sh
TAG=$(git rev-parse --short HEAD)
REPO=asia-northeast1-docker.pkg.dev/paxtech-stg/team-memory

# linux/amd64 is required: an ARM build will not run on Cloud Run.
docker buildx build --platform linux/amd64 -t "$REPO/app:$TAG" --push .
docker buildx build --platform linux/amd64 --target web -t "$REPO/web:$TAG" --push .
```

## Secrets

Generated by Terraform (they land in state, which is why the bucket is
private and versioned): `secret-pepper`, `bootstrap-secret`,
`oidc-flow-secret`, `database-url`.

Supplied out of band, so they never enter state:

```sh
gcloud secrets versions add oidc-client-secret --data-file=-   # WorkOS API key
gcloud secrets versions add extractor-api-key  --data-file=-   # DeepSeek
```

## Migrations

Migrations run on boot, and the schema lock makes that safe when instances
overlap. To run them as a separate step instead, execute the migration
binary that ships in the same image with `TEAM_MEMORY_DATABASE_URL` set;
`cmd/team-memory-migrate` needs no other configuration.

## First login

Claiming the first workspace owner requires a successful OIDC login first,
then the bootstrap secret:

```sh
gcloud secrets versions access latest --secret=bootstrap-secret
```

Check on that first login that WorkOS emits `email_verified: true` in the ID
token. If it does not, bootstrap still succeeds but every later invitation
acceptance fails permanently with 410.
